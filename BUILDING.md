# Building TizenTube Cobalt for Android

This guide builds the Android TV APK from source. It is specific to this
repository and covers the full `gclient` dependency setup, Android toolchain,
build, and device installation.

The build produces a **devel** APK by default. Devel builds include the
on-screen **Test HTTP proxy** button. QA and gold builds use the same native
proxy support but do not show the test button.

## Before you start

The build is a full Cobalt/Chromium Android build, not a small Android project.

- Linux x86-64 host. Ubuntu 22.04 and Debian 12 are known to work.
- At least 16 GB of RAM; 24 GB or more is recommended.
- At least 100 GB of free disk space.
- 8 or more CPU cores are strongly recommended.
- A working `sudo` installation; `install-build-deps.sh` installs host packages.
- Git 2.25 or newer. `depot_tools` may warn about older versions.

You also need an Android device or emulator for installation. The build itself
does not require a device.

## Why `git clone` alone is not enough

This repository is a Cobalt/Chromium checkout. A normal `git clone` does not
fetch the dependencies listed in `DEPS`, the CIPD packages, or the files
generated by gclient hooks. Building such a checkout fails with errors such as:

```text
fatal error: 'services/.../memory_instrumentation.mojom.h' file not found
fatal error: 'gpu/config/gpu_lists_version.h' file not found
```

Those files are not checked into the repository. They come from:

- `gclient sync`: fetches DEPS entries, git submodules, and CIPD packages.
- `gclient runhooks`: generates LASTCHANGE, GPU/Skia version headers, and
  other metadata.
- GN/Ninja actions: generate mojom, protobuf, grit, JNI, and V8/Torque files
  during the build.

Always use a gclient workspace with the repository checked out as `src`.
`DEPS` contains:

```python
gclient_gn_args_file = 'src/build/config/gclient_args.gni'
```

so a checkout with a different directory name, or a symlink outside the
workspace, fails with `Path escapes directory`.

## Quick start: setup script

From a checkout of this repository:

```sh
./scripts/setup-build.sh
```

By default this creates a workspace at `$HOME/cobalt-build`, checks the source
out as `src`, syncs all dependencies, installs host build dependencies,
generates the debug keystore, configures GN, and builds:

```text
$HOME/cobalt-build/src/out/android-arm_devel/apks/Cobalt.apk
```

The default source URL is the checkout containing the script, so local commits
are included. Uncommitted changes are not; commit them first. Pass `--repo` to
build a remote fork instead.

Useful options:

```sh
./scripts/setup-build.sh --help

# Choose a workspace, build type, and parallelism:
./scripts/setup-build.sh \
  --workspace "$HOME/cobalt" \
  --build-type devel \
  --jobs 12

# Build a different fork or a local checkout:
./scripts/setup-build.sh --repo https://github.com/your-name/TizenTubeCobalt.git
./scripts/setup-build.sh --repo "file://$PWD"

# Configure dependencies but do not start the long native build:
./scripts/setup-build.sh --skip-build

# Reuse an already-synced workspace:
./scripts/setup-build.sh --workspace "$HOME/cobalt" --skip-sync
```

If you build from your own local commits, either push them to the repository
used by `--repo`, or pass `--repo "file:///absolute/path/to/checkout"` so
`gclient` clones the source including those commits.

## Manual build

The script automates the steps below. They are useful when debugging a failed
setup or building in CI.

### 1. Install depot_tools

```sh
git clone https://chromium.googlesource.com/chromium/tools/depot_tools.git \
  "$HOME/depot_tools"
export PATH="$HOME/depot_tools:$PATH"
```

Do not replace `depot_tools` binaries with distribution packages. `gclient`,
`autoninja`, and the CIPD client must come from this checkout.

### 2. Create a gclient workspace

The repository must be cloned into a directory named `src`:

```sh
mkdir -p "$HOME/cobalt"
cd "$HOME/cobalt"

gclient config --name=src --managed \
  https://github.com/dyay108/TizenTubeCobalt.git
```

Append the Android target to `.gclient`:

```python
target_os = ["linux", "android"]
```

You can add it with:

```sh
printf '\ntarget_os = ["linux", "android"]\n' >> .gclient
```

If you are building local commits that are not pushed, use a local URL:

```sh
gclient config --name=src --managed \
  "file:///absolute/path/to/your/TizenTubeCobalt"
```

The path passed to `file://` must be the checkout containing the commits you
want to build.

### 3. Fetch dependencies and run hooks

```sh
cd "$HOME/cobalt"
export PATH="$HOME/depot_tools:$PATH"

gclient sync --no-history -j"$(nproc)"
```

This step downloads the Chromium DEPS, Cobalt dependencies, CIPD packages
(JDK, Android SDK/NDK, clang, Rust, Node, siso), and runs the repository hooks.
It can take a long time and temporarily use a lot of disk space.

Verify the generated inputs exist:

```sh
ls build/config/gclient_args.gni
ls gpu/config/gpu_lists_version.h
ls skia/ext/skia_commit_hash.h
```

If those files are missing, `gclient sync`/`runhooks` did not complete.

### 4. Install host build dependencies

```sh
cd "$HOME/cobalt/src"
./build/install-build-deps.sh --no-prompt --no-arm --no-chromeos-fonts
gclient runhooks
```

`install-build-deps.sh` requires `lsb-release` and `sudo`. If it fails because
`lsb_release` is missing:

```sh
sudo apt-get update
sudo apt-get install -y lsb-release sudo
```

### 5. Create the debug keystore

Cobalt's Android APK target signs with:

```text
~/.android/debug.keystore
```

Create it if it does not exist:

```sh
mkdir -p "$HOME/.android"
"$HOME/cobalt/src/third_party/jdk/current/bin/keytool" \
  -genkeypair -v \
  -keystore "$HOME/.android/debug.keystore" \
  -storepass android \
  -alias androiddebugkey \
  -keypass android \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000 \
  -dname "CN=Android Debug,O=Android,C=US"
```

### 6. Configure GN

From the `src` directory:

```sh
cd "$HOME/cobalt/src"
export PATH="$HOME/depot_tools:$PATH"

python3 cobalt/build/gn.py -p android-arm -c devel --no-rbe
```

`android-arm` matches the 32-bit ARM Chromecast build. Other Cobalt Android
platforms include `android-arm64` and `android-x86`.

`gn.py` writes `out/android-arm_devel/args.gn`. It should finish with output
like:

```text
Done. Made 54814 targets from 4028 files
```

### 7. Build the APK

```sh
autoninja -C out/android-arm_devel -j"$(nproc)" cobalt_apk
```

Use `autoninja`, not plain `ninja`, for a normal Android build. The Java
validation steps expect autoninja integration and may fail otherwise with:

```text
AUTONINJA_BUILD_ID is not set
```

The APK is written to:

```text
out/android-arm_devel/apks/Cobalt.apk
```

## Build types

`gn.py -c` selects the build type:

| Type | Proxy settings | Notes |
| --- | --- | --- |
| `devel` | Yes | Recommended for development. Includes debug command-line switches. |
| `debug` | Yes | Debug-oriented, much slower to run. |
| `qa` | Yes | Official-style build with stack traces. |
| `gold` | Yes | Release build. |

The app-local HTTP proxy setting is compiled in all build types. It is configured
from **Settings → TizenTube Settings → HTTP Proxy** and does not modify the
Android system proxy.

## Install and test on a device

```sh
adb devices
adb install -r out/android-arm_devel/apks/Cobalt.apk
```

If an older TizenTube Cobalt APK is installed with a different signing key,
uninstall it first:

```sh
adb uninstall io.gh.reisxd.tizentube.cobalt
adb install out/android-arm_devel/apks/Cobalt.apk
```

Open **Settings → TizenTube Settings → HTTP Proxy**:

1. Enter a proxy such as `proxy.example.com:8080`.
2. Select **Test proxy** to verify the proxy with an HTTPS request.
3. Select **Save**.
4. Restart TizenTube to apply the saved value to Cobalt's network stack.

The proxy is used only by this app. The Android system-wide proxy is not
consulted and does not need to be configured.

Useful checks:

```sh
# Confirm the app is running and which version is installed:
adb shell dumpsys package io.gh.reisxd.tizentube.cobalt | grep -E 'versionName|versionCode'

# Inspect proxy-related log messages and generated request errors:
adb logcat -s starboard:* chromium:* | grep -i proxy
```

## Troubleshooting

### `Path escapes directory` or invalid `gclient_gn_args_file`

The repository is not at `<workspace>/src`, or `src` is a symlink outside the
workspace. Move or re-clone the source into a real `src` directory. Do not use a
symlink for the main solution.

### `memory_instrumentation.mojom.h`, `gpu_lists_version.h`, or `skia_commit_hash.h` is missing

The checkout was not synchronized with gclient. Run, from the workspace root:

```sh
gclient sync --no-history -j"$(nproc)"
gclient runhooks
```

Do not manually copy these headers from another checkout. They are generated
for the exact dependency revisions in `DEPS`.

### `AUTONINJA_BUILD_ID is not set`

Use `autoninja` from `depot_tools`, not the system `ninja`:

```sh
export PATH="$HOME/depot_tools:$PATH"
autoninja -C out/android-arm_devel cobalt_apk
```

### `debug.keystore` is missing

Run the `keytool` command in step 5. Cobalt's `cobalt_apk` target uses
`~/.android/debug.keystore` and will fail during APK packaging without it.

### Java fails with `java.chromium: not found`

Do not point `third_party/jdk/current` at the host JDK or replace its `java`
wrapper. The JDK from `gclient sync` includes the correct `java` and
`java.chromium` files. If the directory is damaged, run `gclient sync` again.

### `libc6:i386` or 32-bit loader errors

Cobalt's V8 build uses a 32-bit host tool. `install-build-deps.sh` installs the
required i386 runtime. On Debian/Ubuntu it may need:

```sh
sudo dpkg --add-architecture i386
sudo apt-get update
sudo apt-get install -y libc6:i386 libstdc++6:i386 libgcc-s1:i386
```

### The build is very slow

Use all available cores and enough RAM:

```sh
autoninja -C out/android-arm_devel -j"$(nproc)" cobalt_apk
```

The first build compiles thousands of Chromium/Cobalt translation units and can
take a long time. Incremental builds are much faster. `ccache` or `sccache` can
be enabled for repeated builds, but is not required for a first build.
